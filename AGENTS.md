# Instructions communes aux agents de développement
Lire PRD.md intégralement avant de coder. Implémenter uniquement le ticket courant du backlog. Ne pas ajouter de fonctionnalités P2/P3 au prototype. Inspecter le dépôt et les versions avant modification ; ne pas écraser les changements utilisateur. Si une décision bloquante manque, la signaler ; sinon documenter une hypothèse réversible dans Docs/DECISIONS.md. Utiliser des assets placeholder originaux/licenciés, sans dépendances payantes non approuvées. Séparer règles C# pures et présentation Unity. Écrire tests et critères d'acceptation avant ou avec le code. Exécuter les tests disponibles, rapporter commandes, résultats et limites. Ne jamais inventer une compilation, un APK ou un test réussi. Ne pas publier, acheter, connecter de SDK externe ni envoyer de données sans accord. À chaque ticket : plan court, implémentation, tests, fichiers modifiés, risques, prochain ticket. Maintenir Docs/STATUS.md. Commencer par P0-01 puis suivre l'ordre du PRD. Si Unity est absent, préparer les fichiers et tests purs possibles, indiquer le blocage ; ne pas prétendre avoir testé dans Unity.
